# 보안 모델과 위협 분석

문서 라이선스: CC BY 4.0. 코드: GPL-2.0-only.

Mingol은 보안 제품이 아니다. 어디까지 믿을 수 있고 어디부터 믿으면 안 되는지 정리한다.

## 1. 신뢰하지 않는 입력과 방어
| 입력 | 방어 | 근거 |
|---|---|---|
| `.mingol` | 매직·버전·플래그·정확한 크기, 헤더+TOC SHA-256, 이름 검증(`..`·절대경로 거부), 엔트리 연속성, 암호화 시 청크별 AEAD, 엔트리 SHA-256 | 모든 비트 반전 전수 검출 테스트 |
| `.mindev`/`.minseen` | 엄격한 JSON 파서(깊이 제한), 스키마 검증, 정규형 CRC-32 `integrity`(손상 검출용, 변조 방지 아님), 알 수 없는 컴포넌트는 기본 오류(`skipUnknownComponents`일 때만 경고) | 손상 입력 테스트 |
| PNG/JPEG/WAV/OGG | 헤더 단계 크기 한도, 할당 0 초기화, 고정 아레나 | 절단·랜덤 손상 수천 회(ASan) |
| glTF | 리졸버 경로 검증(프로젝트 밖 읽기 차단), 로드 결과의 내부 일관성 검사 | 변이 테스트 |
| `.mins` 소스 | 컴파일러 중첩 깊이 제한, 퍼징 | 크래시 0 (의미 정확성은 미검증) |

## 2. `.mingol` 암호화의 한계 (중요)
- ChaCha20-Poly1305(64 KiB 청크) + HKDF-SHA256, 헤더·TOC도 인증. **게임 실행 파일이 키를 알아야 하므로** 실행 파일을 분석하는 공격자는 키를 꺼낼 수 있다. 목적은 *캐주얼한 추출 방지와 변조 검출*이며 DRM이 아니다.
- 암호 구현은 **직접 작성**했고 RFC/FIPS 테스트 벡터 및 Python `cryptography`와 교차 검증했으나 **외부 감사를 받지 않았다.** 중요한 비밀에는 쓰지 말 것.
- 키는 명령줄 인자로 받지 않는다(`--key-file`, `--key-env`, `--passphrase-env`+`--salt`). PBKDF2-HMAC-SHA256 200000회.
- 키 회전·다중 키 없음. 비암호화 아카이브의 SHA-256은 손상 검출용이다(전체를 다시 쓸 수 있는 공격자는 막지 못함).

## 3. 스크립트와 플러그인은 샌드박스가 아니다
- `.mins` VM은 파일/네트워크 API를 기본 제공하지 않지만(기본 라이브러리 없음), **플러그인(DLL/SO)은 프로세스 전체 권한**으로 실행된다. 신뢰하지 않는 플러그인을 로드하지 말 것.
- 플러그인 경계를 넘는 C++ 예외/`longjmp`는 금지(정의되지 않음). ABI 버전 불일치·미선언 이름 등록은 로드 실패로 처리된다.
- VM은 힙 한도(`maxHeapBytes` → `OutOfMemoryError`)와 스택 한도(`StackOverflowError`)가 있으나 **무한 루프 시간 제한은 없다**(워치독 없음).

## 4. 에디터/플레이어
- 플레이어는 콘텐츠 이름을 `isValidRelativePath`로 검증해 프로젝트 밖 경로를 읽지 않는다(폴더 모드 포함).
- 에디터 프로젝트 파일은 신뢰된 개발 자원으로 취급한다(스크립트가 곧 코드).
- 단일 EXE는 PE/ELF에 아카이브를 덧붙이는 방식이라 코드 서명 도구와의 상호작용은 검증하지 못했다.

## 5. 취약점 신고
공개 저장소가 생기면 비공개 신고 채널을 `SECURITY.md`(저장소 루트)에 적을 것. 현재는 정해지지 않았다.
